# T730-I350 Rig
Notes from building T730 based rig for home automation

HW:

First I analyzed potential platforms. I was considering mostly T620 Plus and T730 Thin Clients from HP. Those are most common, cost effective and realiable platforms. Newer HP Thin clients are mostly out of stack or bit to pricy. Many also lacks of PCI slot for x4 Network Card.

T620 Plus have better mechanical/termal design but it is an older machine with older chipset, and I have direct info from another user that it only support IOMMU V1 which was the blocker for him when he try pass through the NICs on his setup. One revision of T620 Plus have not only micro PCIe port but also additional mSATA port. Of course you can alwyas solder connector in later revisions by yourself. So T620 Plus have potentialy one more mSATA port then t730, but its micro PCIe port is definitly less usefull nowadays then m.2 key E port in t730. Of course there are adapters but becouse of avaliable space inside chasis they are not alwyas a good option. T620 plus also have two serial and one parallel port, and option to add VGA port which are not present in t720 in favour of more usb and display ports. Again, nowdays they usefulness is very limited. So at the end my choice was t730.

When it comes to Network Card my idea was to use 4 ports gigabit ethernet card. After lurking in the forums I found out that it will be good when it can support SR-IOV. So most of cheap Intel PRO/1000 are not an option. It looks like prefered cost effective option will be I350T4 card. Unfortuneatly they are not avaliable on the market at the moment, and only option is buying one from scondary market. Geniune Intel verions are less common and more expensive, also I contacted Intel suport and they don't provide firmware upates for them. From the other hand OEMs made for Dell have regular FW updates and they avaliability is better. They don't have a good reputation thou, since Dell disable SR-IOV on them initially. But they reenable that function on FW update couple years ago. So I decided to go with Dell I350T4 card.

It looks like there are no WiFi AC/AX card that have AP mode enable and is fully suported on debian (not to mention FreeBSD) on the market. Many popular Intel card will not even work in this setup since they are using CNVi protocol. Only cards that are confirmed to support AP mode are Atheros modules. But they avalibility is limited and they are mostly chinese clones supporting only WiFi AC and Bluetooth 4.0 (when Intel modules on the market now suports AX and older AC modules suports Bluetooth 5.0). So I decide to use external Microtik AP.

I also want to use Google Coral Edge TPU for image detection in that setup. Google provide modules on USB, micro PCIe, and 3 m.2 modules. In that setup I can use USB, m.2 key A+E and m.2 dual module. I decide to use m.2 dual module but probably t720 not support bifurcation so there will be only one core avaliable (but cost of dual module on farnell has better price/value coefitient then A+E single module from competition). Unfortuneatly I have to wait for avalibility so Initially I will use USB module that I already have.

FW:

First thing I decided to do after obtaining hardware is updating the FW.

We can Update T730 BIOS from Win10 installed on it's drive (not try from Windows IOT systemst but I think it should be also possible), or directly from the BIOS using flashdrive. As always with HP creating the drive manulally is not an easy task since they are changing dir structure of that drives from time to time. So I prefer to create the drive on other computer running windows. And at this time I encountered a problem. Installer throws an error right after the start when I try to do it from VM. After longer googling I find out that the problem lies on notintiutive check performed by installer. Right after start installer checks the UEFI version to decide if it can update BIOS from OS, but when there is no UEFI it not proposing to create a flashdrive but returns with error. So to use it to create flashdrive we have to run it under OS installed in UEFI mode (legacy mode VMs are not an option).

I figured out that I also can update TPM module from version 1.2 to 2.0. It is possible since T730 using SLB9660/SLB9665 chip form Infineon. So according to Infineon datasheet such update is supported. Problem lies in finding right binarry and flashing it to chip, since updates ar allowed only beetween matching FW versions. So first step will be updating TPM 1.2 to maximum avaliable version for that machine. It will be possible using that SoftPaq: https://ftp.hp.com/pub/softpaq/sp82001-82500/sp82133.exe 
Then we should find right binnary that will allow us updating to TPM 2.0. That binnary is not officialy provided by HP for that machine. But we can find it in that SoftPaq dedicated to other HP machines: https://ftp.hp.com/pub/softpaq/sp87501-88000/sp87753.exe
At last we should download SoftPaq providing instruction and scripts that will allow us flashing right binary - it will be: https://ftp.hp.com/pub/softpaq/sp84001-84500/sp84096.exe
To perform procedure we also need BCU tool that we will find here: https://ftp.hp.com/pub/softpaq/sp143501-144000/sp143621.exe
All steps needed to update TPM are performed under Windows but probably update to right binary can be scripteted under Linux, and steps involving BCU maybe can be done directly from BIOS. Don't know if we can use same procedure to update TPM 1.2 to latest version, and find the binary itself, since updater for that was a standalone exe, and since it just work I was not analysing it further.

FW for Dell's I350 can be upgraded directly from the Windows. There is also a updater dedicated to RedHat Linux but it seems not work on Debian based systems. It starts but fails on gathering NICs informations. After updating to latest version of FW I find out that my NICs not have SR-IOV capability. After long investigation I find out that  SR-IOV was enabled in FW 15.0.27 (https://dl.dell.com/FOLDER01772935M/1/FW_release_notes.txt?uid=251ecd72-7594-468f-c8c6-8c94ceb404c9&fn=FW_release_notes.txt) but then disabled by default in FW 20.0.16 (https://dl.dell.com/FOLDER07032138M/1/fw_release.txt?uid=0d3a9d66-4e22-4f61-39eb-1a80ded24894&fn=fw_release.txt). Probably we will be able to enable it from BIOS if we use this card on some Dell server machine. Intel provide tools (https://www.intel.com/content/www/us/en/download/2593/administrative-tools-for-intel-network-adapters.html) that should allow enable SR-IOV but it looks like that it nit support OEM cards. Fortuneatly we can enable it directly from the eeprom using ethtool according to guide in that post:
https://listman.redhat.com/archives/vfio-users/2017-August/msg00086.html
